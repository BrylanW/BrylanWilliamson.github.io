# OSS & Disclosure Readiness

## License Choice

This project uses the **MIT License**, which provides maximum flexibility with minimal requirements.

Key points:
- Allows reuse, modification, and distribution
- Requires only preservation of license text and copyright notice
- No copyleft restrictions
- No patent clauses

This makes it ideal for internal tools or educational resources where simplicity and broad adoption are priorities. The license also minimizes legal risk when the project is modified or reused.

## Vulnerability Report Template

### Contact
- Preferred email or secure contact method  
- Optional: PGP key for encrypted communication  

---

### Product / Version / Environment
- Product name and version  
- Operating system or environment details  

---

### Reproducible Summary
- Clear, step-by-step description of the issue  
- No exploit instructions or sensitive data  
- Include logs, error messages, or indicators if relevant  

---

### Impact Assessment
- Type of impact (e.g., privilege escalation, data exposure, denial of service)  
- Severity level  

---

### Mitigation / Workaround
- Temporary fixes or risk-reduction steps  
- Optional or partial mitigations if full patch is unavailable  

---

### Disclosure Timeline
- Preferred timeline (typically 90 days)  
- Willingness to adjust based on vendor response  

---

## Justification

This template follows best practices from:
- **CISA Vulnerability Disclosure Policy (VDP)**
- **ISO/IEC 29147**
- **CERT Coordinated Vulnerability Disclosure (CVD) Guide**

Key principles:
- Avoid sharing active exploit details  
- Encourage responsible, good-faith reporting  
- Support coordinated disclosure timelines  
- Promote collaboration between researchers and vendors  

This approach improves long-term security while reducing risk to users.
